1. Introduction & Selected OWASP Category

For this assignment, I selected OWASP Top 10 (2021) Category A01:2021 – Broken Access Control.

Broken Access Control currently holds the #1 position in the OWASP Top 10. Access control mechanisms enforce authorization policies so users cannot access resources or execute actions outside their intended permissions. When access controls are broken, attackers can view unauthorized files, steal server configurations, or access sensitive user records.

In this practical lab, I designed and implemented a dummy web application demonstrating Path Traversal (CWE-22) and Improper Access Control (CWE-284) in a file download feature, and also applied Insecure Direct Object Reference (CWE-639) mitigations.

3. Dummy Application Setup & Vulnerability Analysis

I created an academic document distribution portal in Python (Flask). The app allows students to download course materials from storage/public_docs/, while confidential admin credentials reside in storage/confidential/.

Vulnerable Code in vulnerable_app/app.py: 
@app.route("/download")
def download_vulnerable():
    filename = request.args.get("file")
    # Insecure direct join without validation:
    file_path = os.path.join(PUBLIC_DOCS_DIR, filename)
    if not os.path.exists(file_path):
        return f"File not found: {filename}", 404
    return send_file(file_path)

Vulnerability Mechanism:

  1. os.path.join() in Python does not sanitize relative path sequences (../).
  2. Passing file=../confidential/admin_db_credentials.env escapes the public directory and reads internal database credentials.
  3. Passing file=../../.env navigates two levels up to the server root, exposing master secret keys and database connection URIs.

Failure of Naive Blacklisting (.replace('../', '')):

A naive mitigation attempted by developers is stripping ../ with string replacement. In vulnerable_app/app.py, I implemented /download_naive: 

filtered_filename = raw_filename.replace("../", "")

Because single-pass replacement is non-recursive, sending a nested sequence like ....// causes the inner ../ to be stripped, leaving behind ../:
....//confidential/admin_db_credentials.env → ../confidential/admin_db_credentials.env. The attack succeeds completely with HTTP 200 OK.

7. Mitigation Implementation & Code Comparison

In secure_app/app.py, I implemented a Defense-in-Depth mitigation strategy:

  • Canonical Path Resolution: Using os.path.realpath() and os.path.commonpath() to ensure target files remain inside public_docs.
  • Indirect Object References (IDOR Prevention): Using token IDs (doc_id=doc_01) so users never directly specify filesystem paths.
  • Regex Allowlisting: Rejecting illegal characters, directory separators, and traversal markers.
  • Information Leakage Prevention: Returning generic 403 Forbidden responses without revealing directory structure.

9. Conclusion

This lab demonstrates why Broken Access Control is ranked #1 in the OWASP Top 10. Direct file path concatenation without canonical path checks allows attackers to read sensitive files with simple ../ payloads. Naive string replacement like .replace('../', '') is ineffective against nested sequences like ....//. The best and most reliable defenses are canonical path validation and indirect object references.
